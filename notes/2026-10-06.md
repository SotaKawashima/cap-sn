## 1. 今日の目的

追加実験①の全系列分析を終えたため、追加実験②「複数シミュレーションシードによる候補評価の精度改善」へ進む。今日は必要作業を整理し、従来の単純最大化版の候補選定規則を維持する仕様を確定した。その後、許可された第4節の6番まで、実験・分析コードの実装とテスト、dry-runを進めた。commit・push、共用PCでのpilot、本実行はまだ行わない。

**確定仕様：[`multiseed_reoptimization_v1.json`](../experiment_protocols/multiseed_reoptimization_v1.json)。実装・pilot・本実行はこの仕様に基づいて準備する。**

目的は、同一ネットワーク内で、有限反復による偶然に左右されにくい候補を探索し、未知のシミュレーションシードでも良い平均性能を持つかを確認することである。特に、単純最大化 $(1.0,1.0)$ を独立評価で上回れるかを調べたい。ただし、必ず上回る候補が存在するとは仮定しない。

## 2. これまでに決めた実験の方向性

| 項目 | 内容 |
| --- | --- |
| 対象グラフ | 元のBA1000、SNAP ego-Facebook、SNAP Wiki-voteの3グラフ |
| 最適化手法 | BO-GP、CMA-ES、ランダムサーチ |
| 最適化の繰り返し | 各グラフ・各手法で6個の最適化シード |
| 評価回数 | 1回の最適化につき $K=50$ 評価。BO-GPの初期探索もこの50評価に含める |
| 探索変数 | 確実性・有効性。それぞれ $[0.5,1.0]$、適用値は小数点以下4桁 |
| 1候補の評価 | $B=5$ 個のシミュレーションシードブロック、各 $M=100$ 反復。合計500反復 |
| 最適化へ返す値 | 5ブロックを合わせた平均 $J_{\mathrm{cum}}$ |
| 比較条件 | 無介入、単純最大化 $(1.0,1.0)$。候補と同じシード・反復数で評価する |
| それ以外の設定 | 元グラフ、ユーザ設定、基準率、情報投入条件などは従来の通常生成条件から変えない |
| raw保存 | 原則として `pop.arrow` を保持し、反復別指標を再計算可能にする |

ここで増やすのは、**最適化シードではなく、1候補の評価に使うシミュレーションシードと総反復数**である。各最適化実行の最良点を残すなら、候補プールは従来と同じく各グラフ18候補、計54候補となる（重複除去前）。

追加実験①の追加7グラフを、この実験で一斉に再最適化することは予定しない。必要になった場合は、今回選んだ少数の候補を追加グラフで評価する案を別途検討する。ピーク等を加えた多目的化、分散への罰則、最悪シード値の最小化も今回の対象外とする。

### 評価値の計算

候補 $\boldsymbol{x}$ を、探索用シード $s_b$ の下で100反復評価した平均を

$$
\widehat{J}_{s_b}(\boldsymbol{x})
=\frac{1}{100}\sum_{m=1}^{100}j_{s_b,m}(\boldsymbol{x})
$$

とし、最適化手法へ返す値は

$$
\widehat{J}_{\mathrm{multi}}(\boldsymbol{x})
=\frac{1}{5}\sum_{b=1}^{5}\widehat{J}_{s_b}(\boldsymbol{x})
=\frac{1}{500}\sum_{b=1}^{5}\sum_{m=1}^{100}j_{s_b,m}(\boldsymbol{x})
$$

とする。**5ブロックの平均を返して初めて「1評価」が完了する。50評価が250候補になるわけではない。**

$J_{\mathrm{cum}}$自体の定義は変えず、その期待値の推定に使う反復数を増やす。固定グラフ・固定設定の下では、複数ブロックへの分割は別の実験条件を導入するものではなく、監査やばらつきの診断をしやすくするための管理単位である。

## 5. 計算量と実行時間の目安

以下は確定仕様に基づく。候補座標の重複を統合する前の論理件数を示す。

| 処理 | 件数・計算量 |
| --- | ---: |
| 最適化実行 | $3\times3\times6=54$ 回 |
| 候補評価点 | $54\times50=2,700$ 評価 |
| 探索中のシミュレータ呼び出し | $2,700\times5=13,500$ ブロック |
| 探索中の総反復数 | $13,500\times100=1,350,000$ 反復 |
| 探索時の無介入・単純最大化 | $3\times2\times5=30$ ブロック、3,000反復 |
| 新54候補と2比較条件の独立検証 | $(54+3\times2)\times3=180$ ブロック、18,000反復 |
| 最終新9候補と2比較条件の評価 | $(9+3\times2)\times5=75$ ブロック、7,500反復 |
| 旧9候補の補助評価 | $9\times5=45$ ブロック、4,500反復 |
| 最終テストの合計 | $75+45=120$ ブロック、12,000反復 |

本実験の総計は13,830ブロック、1,383,000反復となる。pilot、失敗時の再実行は別枠とする。適用座標が同じ候補は、同一段階・同一設定の正常な出力を確認して共有できるが、論理上の候補と出典はすべて保持する。

元3グラフでの従来実験は、最適化全体が約16.50時間、そのうちシミュレーションが約16.34時間だった。5倍のシミュレーション量へ拡張すると、**探索は約82時間、後段を含めて約84時間**という従来見積もりになる。旧候補45ブロックの補助評価も追加するが、従来の1ブロック当たりの時間からは数十分程度の増加であり、全体は引き続き約84時間台を暫定目安とする。共用PCの負荷や再実行の余裕を含め、4--5日程度を見込む。

これは今回の実測値ではない。追加実験①では大学別Facebookの実行が長時間化したが、今回の対象は元のego-Facebookであり、その時間をそのまま転用しない。共用PCの現状も含め、pilotの実測からネットワーク別・全体の時間と必要容量を更新してから本実行する。

- 失敗・中断したブロックは `_failed_attempts/` に移して残し、同じ座標・シードで再試行する。完了済み出力の破損や設定変更は、自動的に作り直さずエラーとして止める。
- 入力・仕様・実行コード・シミュレータ本体・ライブラリの変更を検出した場合は、その実験への継ぎ足しを拒否する。checkpointは同じ実行環境での再開用であり、外部から取得したpickleは読み込まない。
- 同じ実験の二重起動はロックで拒否する。親の実行処理が終了してもRust子プロセスが残っていれば、子が終了するまでロックを維持する。
- 座標重複の共有は今回は実装せず、すべての論理候補・ブロックを保存する。予算表の件数をそのまま実行する。

### 実行する段階と件数

| 段階 | 実行項目数 | シミュレータのブロック数 | 次段階へ進む条件 |
| --- | ---: | ---: | --- |
| `exploration` | 84（54最適化＋30比較ブロック） | 13,530 | 全50評価×5ブロックと比較条件を監査し、54候補を固定する |
| `validation` | 180 | 180 | 固定済み54候補を検証し、従来規則で各グラフ3候補を固定する |
| `final_test` | 120 | 120 | 新9候補の固定後だけ実行可能。旧9候補と比較条件も同じテストシードで評価する |

探索監査が完了する前は `validation`、新9候補が固定される前は `final_test` を実行できない。異なる候補領域が3個未満となった場合も、勝手に選定規則を変えず確認を求める。最終分析は固定済み候補を変更しない。

from pathlib import Path

print("verified pop.arrow blocks =", blocks)
print("estimated exploration hours incl references =", round(hours + reference_hours, 2))
print("estimated all phases hours excl analysis =", round(hours + all_fixed_hours, 2))
